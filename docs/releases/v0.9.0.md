## 变更

- Claude 表单新增「提示缓存时长」下拉（提供商默认、关闭、五分钟、一小时），落为路由级 `cacheRetention`：提供商默认不写该字段，关闭写入 `none`，两种时长写入对应取值。
- 新增插件配置卡片「Claude 提示缓存」，为工具定义、系统提示、消息三段分别选择五分钟或一小时，并校验 Anthropic 要求的一小时排在五分钟之前。
- 配置卡片顶部只读显示当前生效的分段组合，组合非法时说明原因而不是静默失效。
- 新增预热面板：填入提供商 ID 后，用该提供商最近一次请求的工具与系统提示重发一次 `max_tokens: 0` 的请求，把前缀写入缓存并回报写入的 token 数。（`0.9.1` 已移除该面板，说明见 `v0.9.1.md`。）
- 版本号提升到 `0.9.0`。

## 说明

- 分段缓存与预热依赖 `@dsh-plugin/dsh-loader`：插件用它的 `config` 保存分段配置，用 `patch.global` 改写发往 Anthropic Messages 端点的请求体。未安装 loader 的 Profile 保持原有行为，请求体不被改写。
- 改写只作用于被标记为 Claude 类型、且自身 `cacheRetention` 为 `long` 的路由。其余路由，包括通用的 `anthropic-messages` 自定义提供商，一律不受影响。
- 预热走补丁之前的 `fetch`，因此不会把重放请求本身记成「最近一次请求」。
- 配置写入 `<profile>/config/claude-cache/config.json`，与 Profile 补丁文件分离，因此不影响现有的路由配置。
- 一小时缓存的写入按基础输入价的 2 倍计费，默认只有工具定义与系统提示使用一小时。
- 零输出预算无法重放的请求会说明原因并跳过：预算思考的 `budget_tokens` 与 `max_tokens` 之间存在取值约束，压缩输出上限会违反它或写入真实请求无法命中的条目；携带结构式输出配置的请求同样无法用零输出重放（适配器当前不会发出，属防御性检查）。自适应思考与 `output_config.effort` 一律原样保留，因为它们会被渲染进提示词。
- 每条路由的 `baseURL` 在匹配前统一规范化（协议、主机大小写、默认端口、末尾斜杠），避免把 `https://API.Example.com:443` 与 `https://api.example.com` 当成两个端点。
